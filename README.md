# Kathmandu SMP Shop — Android wrapper

This is a Capacitor Android shell for the existing live Kathmandu SMP E-Shop.

- App name: Kathmandu SMP Shop
- Android application ID: `com.kathmandu.smp.shop`
- Live shop: https://kathmandu-minecraft-smp-e-shop-br6yqx.v2.appdeploy.ai/
- Build output: `android/app/build/outputs/apk/debug/app-debug.apk`

## Build an installable test APK with GitHub Actions

1. Create a new **private** GitHub repository.
2. Upload the contents of this folder to the repository (the `.github/workflows` folder must be included).
3. Open the repository's **Actions** tab.
4. Run **Build Kathmandu SMP Shop APK** (or push to `main`).
5. When the workflow finishes, open its run and download the `kathmandu-smp-shop-debug-apk` artifact.
6. Extract the artifact ZIP; install `app-debug.apk` on your Android phone. You may need to allow installation from that source.

## Important

- This is a native Android APK shell that loads the existing hosted shop. Orders, admin, tracking, and UPI remain on the existing backend.
- An internet connection is required.
- The workflow produces a **debug APK** for testing and direct installation. A Play Store release or production-signed APK requires a release keystore and secure signing configuration.
- Do not commit signing keys or passwords to the repository.
- The initial Android project is generated by Capacitor in CI, so the `android/` directory is intentionally not included.
- Replace the default Capacitor launcher icon with your approved shop icon before public distribution.

## Supabase + Cloudflare Pages migration branch

This branch contains the in-progress replacement for the AppDeploy-hosted shop.
The original `main` branch is intentionally left unchanged.

### Build locally

1. Install Node.js 22.
2. Run `npm install`.
3. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in a local `.env` file.
4. Run `npm run build`. The static website is written to `dist/`.

The Supabase key used by the browser must be the project's publishable/anon key.
Never put a Supabase service-role key in browser code or GitHub build variables.

### Supabase setup

The initial tables are in `supabase/schema.sql`. Apply the operations in
`supabase/migrations/202611260001_shop_operations.sql` in the Supabase SQL Editor
after the initial schema. Configure Google as an Auth provider and add the final
Cloudflare Pages URL to Supabase Auth's allowed redirect URLs and Google OAuth
authorized redirect configuration.

The first owner role must be assigned manually to the intended account from the
Supabase SQL Editor after that account has signed in once:
`insert into public.shop_team_roles(user_id, role) select id, 'owner' from auth.users where lower(email)=lower('YOUR_EMAIL') on conflict(user_id) do update set role='owner';`

### Cloudflare Pages

Connect this repository's `supabase-cloudflare-migration` branch to Cloudflare Pages.
Use build command `npm run build`, build output directory `dist`, and add the
environment variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
Do not switch production traffic until the Supabase SQL migration and Google login
have been tested on the Cloudflare preview deployment.
